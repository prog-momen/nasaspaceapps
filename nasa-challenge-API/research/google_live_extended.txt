# Gemini 3.8 Live Extended Thinking

Gemini 3.8 Live Extended Thinking (`gemini-3.8-live-extended-thinking`) is our
high-reasoning audio-to-audio Live API model for complex, multi-step problem
solving during real-time voice interactions. It processes configurable
background reasoning (`low`, `medium`, `high`), thought summaries, and
asynchronous tool calls while streaming continuous audio responses.

For low-latency conversational voice experiences without background reasoning
delays, see [Gemini 3.8 Live](/docs/models/gemini-3.8-live).

## Upgrading to Gemini 3.8 Live Extended Thinking  {% id="upgrading" %}

Gemini 3.8 Live Extended Thinking introduces background reasoning during live
audio sessions. When integrating this model, update your client state management
to handle asynchronous reasoning signals:

*   **Asynchronous reasoning protocol**: When interacting with models that use
  asynchronous reasoning, `turnComplete: true` no longer signals that the
  model is completely idle. The server may continue processing background
  reasoning or tool calls. Keep your client listening for subsequent server
  messages (such as tool calls or audio frames) after `turnComplete: true`
  arrives.
*   **Monitoring `interaction_status`**: Check `server_content.interaction_status`
  on incoming
  [`BidiGenerateContentServerContent`](/api-reference/live#BidiGenerateContentServerContent)
  messages to determine the current server state before closing the session:  *   `IN_PROGRESS`: The server is actively processing user input, running
    background reasoning, or awaiting responses for asynchronous tool calls.
    Additional model output or tool calls may follow.
  *   `IDLE`: The server has finished all processing, reasoning, and tool
    calls. The session is idle and waiting for user input.

*   **Function calling**: Function calling is exclusively asynchronous
  (`behavior: NON_BLOCKING`). Synchronous blocking mode returns an error, and
  function scheduling options (`SILENT`, `WHEN_IDLE`, and `INTERRUPTED`) are
  not supported. See
  [Asynchronous function calling](/docs/live-api/tools#async-function-calling).
*   **Thinking configuration**: Configure background reasoning using
  `thinking_config` in your session setup with `thinking_level` values `low`,
  `medium`, or `high`. Note that `MINIMAL` is not supported. See
  [Thinking in the Live API](/docs/live-api/thinking).
*   **Client content updates**: `send_client_content` is supported throughout
  the entire session lifecycle (both initial history seeding and mid-turn
  context updates) with explicit roles (`user` or `model`). Setting
  `turn_complete=true` immediately interrupts active generation. See
  [Incremental content updates](/docs/live-api/capabilities#incremental-updates).
*   **Proactive audio**: Permanently enabled. Setting `proactive_audio: false`
  returns an error.
*   **Affective dialogue**: Removed from the API. Remove any
  `enable_affective_dialog` configurations from your setup.

For a feature comparison across all Live API models, see the
[Model comparison](/docs/live-api/capabilities#model-comparison) table in the
capabilities guide.
