# Gemini 3.8 Live

Gemini 3.8 Live (`gemini-3.8-live`) is the default option for low-latency,
audio-to-audio voice agent experiences and real-time dialogue without
reasoning-induced delays. It supports interleaved reasoning, asynchronous and
synchronous function calling, full-session client content updates, and built-in
proactive audio.

For complex agentic tasks requiring multi-step reasoning and configurable
thinking budgets, see
[Gemini 3.8 Live Extended Thinking](/docs/models/gemini-3.8-live-extended-thinking).

## Migrating from Gemini 3.1 Flash Live  {% id="migrating" %}

Gemini 3.8 Live delivers ultra-low latency audio-to-audio interactions and
expands support for asynchronous workflows. When migrating from
`gemini-3.1-flash-live-preview`, review the following updates:

*   **Model string**: Update your model string from
  `gemini-3.1-flash-live-preview` to `gemini-3.8-live`.
*   **Thinking configuration**: `thinking_level` is not supported in
  `gemini-3.8-live` because interleaved reasoning is built in. Omit
  `thinking_level` and `thinking_config` from your session setup. If your
  application requires configurable background reasoning (`low`, `medium`, or
  `high`), use
  [`gemini-3.8-live-extended-thinking`](/docs/models/gemini-3.8-live-extended-thinking).
  See [Thinking in the Live API](/docs/live-api/thinking).
*   **Asynchronous function calling**: Asynchronous execution (`behavior:
NON_BLOCKING`) is the default function calling mode. You can still use
  synchronous blocking mode for backward compatibility by setting `behavior:
BLOCKING` on your tool declarations. Function scheduling options (`SILENT`,
  `WHEN_IDLE`, and `INTERRUPTED`) are also supported. See
  [Asynchronous function calling](/docs/live-api/tools#async-function-calling).
*   **Client content updates**: `send_client_content` is supported throughout
  the entire session lifecycle (both initial history seeding and mid-turn
  context updates) with explicit roles (`user` or `model`). Setting
  `turn_complete=true` unconditionally interrupts active model generation. If
  you send content without `turn_complete`, the server waits for subsequent
  messages before responding. See
  [Incremental content updates](/docs/live-api/capabilities#incremental-updates).
*   **Proactive audio**: Proactive audio is permanently enabled. Setting
  `proactive_audio: false` returns an error, so omit `proactive_audio` if you
  are migrating code that disables it.
*   **Affective dialogue**: Affective dialogue is removed from the API. Remove
  any `enable_affective_dialog` configurations from your setup.
*   **Turn coverage**: Defaults to
  [`TURN_INCLUDES_AUDIO_ACTIVITY_AND_ALL_VIDEO`](/api-reference/live#RealtimeInputConfig.TurnCoverage).
  Video frames are sent to the model by default, so send frames only when
  needed to manage context and cost.
*   **Response modalities**: Audio is the only supported response modality
  (`response_modalities=["AUDIO"]`). Enable `output_audio_transcription` if
  your application requires a text transcript. See
  [Audio transcriptions](/docs/live-api/capabilities#audio-transcription).

For a feature comparison across all Live API models, see the
[Model comparison](/docs/live-api/capabilities#model-comparison) table in the
capabilities guide.
